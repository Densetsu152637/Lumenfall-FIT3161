## Full scope and review contract
Materially improve existing startup/slots/save feedback/dialogue/quest objectives/inventory controls using existing owners. Provide keyboard/gamepad focus, cancel, scrolling, long choices/text and responsive sizing; explicitly separate offline checks from device/render acceptance. One owned overlay input gate must block dialogue/menu/journal/wheel leaks and survive disabling/reloading without releasing another owner. Opening-frame E must not skip dialogue. Preserve Nunito licensing, speaker frames, rich-text DialogueTextReveal, inventory flags, current-slot behavior and explicit overwrite confirmation.

## Implemented
- Existing IMGUI presenters are materially improved in place; event/quest runtime, inventory discovery flags, spell progression and GameSaveManager remain authoritative. No package, scene, prefab, asset artwork or licensed font changes.
- `OverlayInputGate` in GameEvents provides per-owner acquire/release, excluding only the current owner when checking its input. Transition frames consume input so opening or closing an overlay cannot leak the same press into gameplay. Static gate and compatibility inventory flag reset at SubsystemRegistration. `GridMover.SetMovementLocked(object owner, bool)` composes with the existing legacy transport lock; only the matching owner releases its token.
- Startup, dialogue, inventory/journal, save panel and spell wheel use the gate. GridPlayerInput (including move-completed repeats) and NPC interaction consult it. Spell wheel uses owner locks, keyboard Q/gamepad RB opening, arrows/stick selection, Enter/A cast and Esc/B cancellation alongside existing mouse controls.
- Dialogue retains Nunito, speaker frames and rich-text reveal. Opening/new-node frames reject continuation, keyboard/gamepad can reveal/continue/select choices or cancel, and long bodies scroll. Focused choices request scrolling once using their measured GUILayout rectangle, including wrapped choices, without continually overriding mouse scroll.
- Dialogue and inventory capture the exact subscribed runtime and rebind after runtime replacement; disable releases owned locks and unsubscribes captured delegates. Polling only compares the current runtime reference; it avoids requiring a sibling branch's unmerged RuntimeChanged event.
- Journal adds Active/Completed objectives derived from current runtime and existing authored puzzle definitions. Areas and puzzle objects use readable presentation names; stable IDs remain unchanged. Target conditions reflect authored powered/connected/revealed/frozen/aligned/rotation/destination requirements. No speculative puzzle rules or duplicate quest model. Inventory/spell/encyclopedia pages scroll, left/right navigation changes page, and Tab/View/Esc/B or Close exits.
- Startup shows focus, skips empty slots for keyboard/gamepad, supports cancel/back, and adjusts existing master volume with left/right. A uniform virtual 640x720 stage scales down the menu to avoid overlapping slot/confirmation layouts on small displays. Existing artwork stays intact with a separate focus marker. Full-slot replacement has explicit Replace SLOT 1/Cancel choices, defaulting to Cancel. Failure reasons from SaveFailed remain visible, including while overwrite confirmation is active. CurrentSlot changes after a successful load/start.
- Current-slot save panel opens with F9/gamepad Menu or mouse; F5 saves. Save/load/close have focus and device hints. Reload asks for confirmation with Cancel selected, preserves current-slot semantics, and displays exact save/load failure feedback. Runtime's GameSaveInput adapts InputSystem without adding a GameEvents -> Runtime assembly cycle. Save event subscriptions are paired with enable/disable.
