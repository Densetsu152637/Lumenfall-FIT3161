## Full acceptance contract and implementation

1. Orio's quest starts only through its NotStarted acceptance. Opening, leaving, accepting without finishing, and abandoning the terminal lesson do not unlock Rotara. Completing the terminal accept or Active hint lesson unlocks Rotara while `orio_patch_notes` is Active. Repeating the hint recovers an abandoned lesson. `spellRewardQuestId=orio_patch_notes` guards the existing dialogue reward extension; its saved `spell.unlocked.Rotara` flag is idempotent.
2. The existing single gear is the provisional puzzle. Choose Rotara on the existing spell wheel and use the rebound Interact key (default F) at the mechanism, or the existing spell cast interaction. Acceptance no longer substitutes manual hand-turns for learning Rotara. Rotara rejects targets without a `rotara` tag and nonfinite rotations.
3. Each successful Rotara cast adds90 clockwise, snapping to a normalized quarter turn. Authored180 follows **180 ->270 ->0 ->90**. Negative and wrapped saved angles normalize; wrong orientations, fractional near-misses and nonfinite values fail the target test. There is no inferred multi-component chain.
4. Preserve the existing animated gear, red pointer, fixed teal notch and solved color. Nearby feedback displays current angle, target, clockwise direction, selected-spell/key instructions, unfinished lesson, practice-only duplicate and completed quest status. Text supplements color. This rendering requires manual Unity verification.
5. Completion stays in Orio's existing report conversation. Both report visibility and the nonrepeatable completion event invoke `OrioMechanismAligned`, using the **current live world state and current runtime**: Active quest, learned Rotara, ready map, exact map/object/tag, compatible object and normalized90. The legacy readiness flag is feedback only; spoofed or stale saved flags cannot bypass the live condition. Direct event triggering before lesson or at an unrelated target fails. Automatic QuestPuzzleMonitor completion remains absent for Orio by design.
6. The custom condition is a stateless delegate registered from area attachment and SpellCaster's captured runtime subscription, and refreshed by active gear presentation. It retains no destroyed gear, previous state service, map instance or old runtime. Missing registration fails closed. GameEventCatalog's custom-handler warnings are expected; the handler is provided by the live integration.
7. Retry policy: while Active, overshooting is reversible through continued clockwise casts; three more quarter turns return to90. No quest-specific reset UI or world-wide reset is introduced. Completion remains durable after later practice turns. Existing world/quest save providers preserve partial or solved rotation, lesson flags, quest status and the nonrepeatable event. Existing `eastForest` save normalization is retained.

## Rune dais (replaces the provisional single gear)

The single gear is replaced by a rune dais of three discs and four floor sockets, implemented in [`OrioRuneDiscPuzzle.cs`](../../Lumenfall/Assets/_Project/Systems/Quests/OrioRuneDiscPuzzle.cs). Casting Rotara at a socket turns every disc that socket touches by one clockwise quarter turn, so the discs must be solved together. All of its objects are registered in code before `EndMapRebuild`, following the Stella relic board pattern, so no area prefab, area asset or map JSON changed.

The F04 glade is too small for the dais, so it stands in the deep forest area (`deepForest`), a 20 by 20 authored area with walled floor at x 1–11, y 4–15. Players reach it through the existing west forest portal `P.F01` at `(5,24)`, just west of Orio at `(8,23)`, and arrive by `P.DF00` at `(1,10)`. The portal is always open, and the dais stays inert until the quest is accepted. The dais is centred at `(7,11)`; its stone ring stays inside the walls and clear of the entry portal and the area spawn at `(3,10)`. The dais is the only Orio puzzle. The old single gear `mechanism.orio.rotate`, at westForest `(8,21)` and as a campus copy at `(25,34)`, was removed from both area prefabs, both area assets and both map JSON files, together with their `quest.orio.patch-notes` rotate-to-90 targets. `RotaraGearMechanism` was deleted. Its quarter-turn helpers (`NextQuarterTurn`, `RotationMatches`) now live on `OrioRuneDiscPuzzle`, and the spell chip no longer moves up for a gear status panel. The centre socket keeps the `mechanism.orio.rotate` id because Orio's completion condition names it. An earlier version put the dais in a code-built rune hall reached by its own teleport pads. That hall and both pads were removed when the dais moved here.

The dais is styled as a forest shrine so it fits the area. It has a moss floor inside a ring of old stone, ringed by small standing stones, moss tufts and red-capped mushrooms. The weathered discs carry lichen and a carved arrow rune that glows firefly-gold. The fixed notch each rune must point at is teal. The sockets are tree stumps topped with a glowing firefly orb, which brightens when the player is in range, and vines trace which discs each socket turns. A few fireflies drift above the dais. Solved runes and the floor turn leaf-green. All of it is built from primitives at runtime with a fixed seed, has no colliders and never blocks a tile.

Every disc targets rotation 0, with its rune pointing north at a fixed teal notch. The authored starting angles make the intended answer north 3, centre 2, west 2 and east 1 presses. Other press orders also solve it, and four presses on one socket return its discs to where they started, which keeps trial and error recoverable without a reset control. Socket links apply only in the deep forest, so the same ids on any other map never turn the discs. Discs reject direct casts, so a disc can't be turned on its own.

Completion keeps the existing contract: Orio's `report` choice and `complete_orio_patch_notes` both evaluate `OrioMechanismAligned` against live world state. It requires the Active quest, learned Rotara, the deep forest's centre socket, and all three deep forest discs at rotation 0 with the disc tag. The player reports in the west forest, so the check reads the deep forest through `WorldStateService.TryGetObjectInMap`: live while there, otherwise from the snapshot archived when the player left. A deep forest that has never been visited fails closed. The legacy `orio.patch_notes.mechanism_aligned` flag remains feedback only. New games restart the discs at their authored angles; saved and archived disc angles are re-applied through `spell-world-state`.

Interaction: once Rotara is learned, the interact key (default F) casts the selected spell at the nearest socket within one tile, which is highlighted. Before the quest is accepted the dais is inert. Vines on the floor show which discs each socket turns, and the socket's orb and its vines flash when it is pressed. Turning is ignored while a linked disc is still animating. No on-screen guide text is shown at the dais; Orio's dialogue carries the instructions.
