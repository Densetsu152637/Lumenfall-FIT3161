# Audio clip handoff and integration

Music tracks live in `Resources/Audio/Music/`. `Resources/Audio/audio-manifest.json` declares 32 cues; `music.menu`, `music.forest`, `music.campus` and `music.dormitory` are approved, and every other cue is still `missing_approved_media` and stays silent. The service exposes `GetClipStatus(id)` and reports configuration issues once at initialization. It never creates sounds or imports media automatically.

For each cue, supply an approved, licensed `AudioClip` inside a Resources directory, set `resourcePath` without the Resources prefix or extension, and set `approvalStatus` to `approved`. Preserve cue IDs. Retain provenance/license/owner and replacement decisions in the media handoff. Music and ambience cues must loop; Sfx cues must not loop. Gain is finite in [0,1]. No AudioMixer, Editor or prefab setup is needed. Verify loop seams, fades, perceived balance and platform import settings in licensed Unity Play Mode before audible acceptance.

`AudioMixSettings.GetVolume(AudioBus)` / `SetVolume(AudioBus,float)` / `ResetDefaults()` and parameterless `Changed` own normalized Master/Music/Sfx/Ambience preferences. Read-only Master/Music/Sfx/Ambience properties are available. Keys are `lumenfall.master-volume` (preserved), `lumenfall.music-volume`, `lumenfall.sfx-volume`, `lumenfall.ambience-volume`. Defaults are 1 / 0.7 / 0.85 / 0.65. Invalid values are repaired. Preferences persist independently of game save slots. `AudioFeedbackService` alone applies master to `AudioListener.volume`; source buses never multiply master a second time. Settings/UI integrations must call this authority.

`AudioFeedbackService.PlayUi(AudioUiCue.Confirm/Cancel/Open/Error)` is safe when playback service is absent. Startup button confirmations and dialogue opening already invoke cues. Production UI should call this API on confirmed actions, without replaying each GUI draw. Startup provides all four bus sliders; keyboard/gamepad production controls belong to the production UI branch.

Music is chosen separately from context. From New Game's START until the opening cutscene and its first-thoughts dialogue finish (`CutscenePlayer.OpeningInProgress`), music and ambience are silent, so the arrival's own chord plays alone; one second after that dialogue closes, the forest track fades in. The title menu (`StartupMenu.IsMainMenu`, not the in-game save picker) plays `music.menu`. Otherwise `AudioContextPolicy.MapMusicCue` picks the map's track: forest maps and `orioDaisRoom` play `music.forest`, `B01.*` (Dormitory) plays `music.dormitory`, and campus, every other building and the trial rooms play `music.campus`. Dialogue, mystery and sleep switch to `music.<context>` only once that cue is approved; until then the map's track keeps playing, ducked as below.

Context priority: Sleep > Dialogue > Mystery > map. `westForest`/`deepForest`/`eastForest` select Forest, `campus` selects Campus, remaining authored IDs select Interior, and no map is Silent. Story flags drive mystery with `chapter1.key_handover && !chapter1.sleep && !chapter1.complete`, sleep with `chapter1.sleep && !chapter1.complete`, and wake on rising `chapter1.complete`. Optional explicit flags `audio.mystery`, `audio.sleeping`, `audio.woke` OR into those predicates. Sleep/wake cues follow derived rising edges so aliases do not duplicate cues; replacement/bind/state restore seeds edges without historical replay. Event metadata `audioCue` may name a manifest one-shot. `audioContext` metadata is not supported.

Map rebuild, runtime replacement, scene reload, and disable/re-enable capture and detach subscriptions. Map restore refreshes context; historical quest/wake/sleep cues are not replayed. Completing a live quest emits `quest.complete`. Player `MoveCompleted` emits the map surface step (teleport/blocked movement does not). Existing `SpellCaster.CastCompleted` emits `spell.<spell>` or `spell.no-change` where the baseline actually raises it. Opening and closing the spell wheel plays `ui.spellwheelopen` and `ui.spellwheelclose` (not when the player is disabled with the wheel open). Baseline early spell rejections have no event: merging spell-feedback must replace this subscription with its `CastFeedback` event, Applied => spell ID, NoChange => spell.no-change, other failures => ui.error, and avoid subscribing twice.

Music and ambience use two loop sources each with a 0.6 second unscaled fade. Dialogue ducks music to 0.4, ambience to 0.6; sleep ducks both to 0.3. These gains are provisional until approved media can be listened to. The eight-source transient pool drops excess concurrent cues; no per-event objects are instantiated. Loops and UI cues are 2D; gameplay one-shots use provisional spatialBlend 0.2 at the player position, with Unity default attenuation. No visual animation or reduced-motion preference is introduced.

Gameplay pause keeps music and UI feedback available, pauses ambience and existing gameplay voices, and rejects new gameplay cues. Application pause pauses all channels. Empty voices never become owned paused voices, leaving startup UI capacity available. Fades use unscaled time; no AudioListener.pause or Time.timeScale mutations occur. Audible/spatial/device/render acceptance remains pending. Dependency pointer/GetComponent checks run per frame; player searches occur only on scene/map/world replacement.
